# Center 页面 · 两套重构方案 v2.0

> 基于你这一轮的反馈重做，不再沿用 v1 的「深空 + 模拟器 + 假场景」。
> 两条硬底线：**界面必须是真的**、**动效必须像苹果那样有节奏**。
> 两套方案风格完全不同，都符合「高级科技感」，可以二选一，也可以取长补短。

## 二、调研结论

### 2.1 苹果的做法（Studio Display / MacBook Pro 产品页）

- **一屏只讲一件事**：大标题通常只有 3–6 个词，下面一句解释，再给一个视觉。
- **文案克制**：不列功能点，用「A sight to be bold.」这种短句定调，细节留给下面的模块。
- **滚动是镜头**：产品在滚动中旋转、拆解、合拢；每一段有固定的停留区（pinned），不是每个元素都在飘。
- **技术上**：Apple 产品页大量使用手写 GLSL 着色器 + 滚动驱动的 3D 变换，而不是视频贴图；Safari 已原生支持 scroll-driven animation。

### 2.2 你给的两张灵感图（Dtail / Stanislav Hristov）

- 界面不是贴在页面上，而是**浮在空间里**：主窗口 + 次级浮层 + 背景光晕，三层不同景深。
- 窗口有**轻微透视角度**，不是正面平铺；边缘有高光、环境反射和柔和投影。
- 背景只有一个大弧面光源，颜色统一，没有多余装饰。

### 2.3 结论

高级感来自三件事，不是特效数量：

1. **真实的界面**（截图必须来自真软件）；
2. **正确的光**（一个主光源、统一的色温、柔和投影）；
3. **克制的运动**（只在关键节点动，动就动到位）。

## 三、两套方案共用的基础

### 3.1 真实界面资产管线（解决「界面不像」）

1. 用已解包的 Center 前端（Tauri WebView）在无头浏览器里运行；
2. 注入 mock 桥接数据（27X1QE-500 / 3840×2160 / 165Hz / 10-bit），逐个切换 6 个导航；
3. 以 2× 分辨率截取窗口本体，导出 WebP；
4. 在页面中用 CSS 3D 平面承载，叠加玻璃高光、环境反射与投影；
5. 现场可交互区按真实界面的 DOM 结构与间距重建，只保留必要控件。

这一步是两套方案共同的地基。**没有真实截图，任何方案都会显得假。**

### 3.2 动效系统

- 滚动进度统一由一个 `rAF` 写入 CSS 变量（`--p` 0→1），组件只消费变量，不在 React 里逐帧重渲染。
- 三个 pinned 镜头段：首屏归正、界面拆层、功能推进；其余区块只做一次性入场。
- 所有动效使用 `cubic-bezier(.16, 1, .3, 1)`，时长 600–900ms；不做弹跳、不做无限漂浮。
- `prefers-reduced-motion` 下全部退化为静态最终帧；不支持 `ResizeObserver` / `IntersectionObserver` 的旧内核已有降级封装。

### 3.3 数字老虎机

- `SlotNumber`：每一位是一列 0–9，进入视口后按位错峰 60ms 滚动，900ms 停稳。
- 只用于「6 个模块 / 8 档预设 / 40+ 参数」这类有分量的数字；正文里的数字不动。
- 屏幕阅读器读最终值，动画层 `aria-hidden`。

### 3.4 文案原则

- 页眉一行，主标题一行，副文案最多两句；每个模块最多 3 个短标签。
- 不写「赋能、焕新、全方位、极致」这类空词；只写具体动作和结果。
- 不写不存在的功能（v1 的「云同步」已删除）。

## 四、方案 A · 穹顶（Dome）

**一句话**：一块发光的弧面托住真实的 Center，滚动就是一次镜头推进。

### 4.1 视觉

- 底色：深海军蓝到近黑，统一冷色温。
- 主光源：画面底部一条**巨大的弧形穹顶**，不是平直光带；弧线从画面两侧升起，中心最亮，向外衰减。
- 界面：真实 Center 窗口浮在穹顶前方，带 6°–10° 的透视角度、玻璃高光、底部柔和投影。
- 次级浮层：右下角一块「应用联动」小面板、左上角一个快捷亮度浮层，分别以不同景深跟随滚动。
- 不出现任何星点、粒子、跟随光斑。

### 4.2 页面结构

**① 首屏（100vh，pinned 1.2 屏）**

- 页眉：`CENTER 1.3 · 显示控制中心`
- H1：`全新升级 Center`
- 副文案：`把亮度、色彩、刷新率和固件，收进一个窗口。`
- 主按钮：`下载 Windows 版`；右侧只放版本、大小、日期，不放「在线试用」。
- 镜头：初始窗口 `rotateX(10deg) rotateY(-7deg) translateZ(-60px)`，滚动 0→0.35 时归正并前移；穹顶亮度同步增强。
- 数字条：`6` 个模块、`8` 档预设、`40+` 项参数，进入时老虎机滚动。

**② 六个模块（静态，不 pin）**

- 标题：`一块屏，六种掌控`
- 六张卡不做悬浮乱动，只在悬停时提亮边框；点击后滚动到下方对应的真实界面镜头。
- 每张卡只有：编号、模块名、一句 12 字以内的说明。

**③ 界面拆层（pinned，约 1.6 屏）**

- 真实 Center 窗口放大到屏幕中央；
- 滚动时，窗口的「侧栏 / 内容区 / 状态栏」三层沿 Z 轴轻微分离，像拆解图；
- 每一层旁边出现一条短线标注：`六个导航，一屏直达` / `参数改动即时写入` / `状态栏同步读数`；
- 分离到最大后合拢，进入下一段。

**④ 真实操作（pinned，约 1.4 屏）**

- 保留一个**可操作的**真实界面：亮度、对比度、色域、六轴；
- 预览区不再画风景，改为**校准测试图**（彩条 + 灰阶 + 色块），拖动滑条时测试图实时变化；
- 六轴滑条可拖，数值与状态栏同步；
- 文案：`调校，不必再猜`，副文案一句。

**⑤ 应用联动 / 固件（交替图文）**

- 应用联动：一张真实「选择 Windows 进程」界面截图，配一条进程 → 预设的动画连线；
- 固件：真实的版本检查界面，配一个会走完的进度环（进入视口才播放一次）。

**⑥ 支持设备 / 下载 / FAQ**

- 支持设备：真实型号列表，不做花哨动效；
- 下载：版本卡 + SHA-256 + 三步；
- FAQ 手风琴。

**⑦ 页尾**

- 穹顶弧线在底部再次出现，窗口缩小退入光里；
- H2：`现在，开始调校。`
- 下载按钮。

### 4.3 文案草案

```
页眉    CENTER 1.3 · 显示控制中心
H1      全新升级 Center
副文案  把亮度、色彩、刷新率和固件，收进一个窗口。

模块一  基础显示    亮度、对比度、八档预设
模块二  电竞设置    暗部增强、准心、刷新率
模块三  专业色彩    色域、色温、伽马、六轴
模块四  图像调节    HDR、DSC、RGB 增益
模块五  输入与双模  DP、HDMI、USB-C
模块六  设备与升级  灯效、语言、固件 OTA

拆层段  六个导航，一屏直达
操作段  调校，不必再猜
联动段  游戏一开，模式自己切
固件段  升级，不用教程
下载段  现在，开始调校。
```

### 4.4 技术要点

- 穹顶：WebGL 片元着色器，用 `distance` 到弧心的距离算发光强度，叠加两层高斯与抖动噪点；不做 CSS `blur`。
- 真实窗口：截图 + `transform-style: preserve-3d`；拆层用三个绝对定位平面，共用同一张截图的不同裁切区域。
- 滚动：`position: sticky` + `IntersectionObserver` 计算进度；支持 `animation-timeline: view()` 的浏览器优先走 CSS。
- 性能：首屏只加载 1 张主界面截图（≤400KB），其余截图进入视口前懒加载。

## 五、方案 B · 校准台（Calibration Studio）

**一句话**：把 Center 放进一间安静的光学工作室，用测量的方式讲软件。

### 5.1 视觉

- 底色：暖白 / 浅灰（`#F5F6F7`），柔和环境光，像 Apple Studio Display 的产品页。
- 主色：深墨黑文字 + 品牌蓝作为唯一点缀；没有霓虹、没有星空。
- 界面：真实 Center 窗口以轻微角度放在浅色背景上，投影很轻，边缘有一道细高光。
- 细节：细刻度线、等宽数字、极细分割线；大量留白。
- 动效：安静、精确；只有「对比滑杆、旋钮、镜头推进」三类交互。

### 5.2 页面结构

**① 首屏（100vh）**

- 页眉：`光魂 Center · v1.3`
- H1：`全新升级 Center`
- 副文案：`专业调校，回到直觉。`
- 视觉：真实 Center 窗口悬浮在浅灰背景中，滚动时从 6° 缓慢归正；
- 底部一行极细的规格条：`Windows 10 / 11 · 6 个模块 · 8 档预设 · OTA`，数字老虎机滚动。

**② 前后对比（pinned，约 1.5 屏）**

- 一张**校准测试图**（彩条 / 灰阶 / 肤色块），中间一根可拖动的分割线；
- 左半边是「未调校」，右半边是「调校后」，拖动即时对比；
- 文案：`看得见的改变` + 一句：`同一块屏，调之前和调之后。`
- 这是整页的第一个交互，也是最能说明软件价值的交互。

**③ 参数特写（pinned，约 1.4 屏）**

- 镜头从整窗推进到「专业设置」面板，六轴滑条放大；
- 用户可直接拖动六轴，测试图与数值同步；
- 文案：`每一个参数，都有刻度。`

**④ 三个短章（静态交替）**

- `一个进程，一套预设` — 应用联动；
- `开机就在，不用重设` — 自启动与设置记忆；
- `固件升级，交给它` — OTA 与校验。

**⑤ 支持设备 / 下载 / FAQ**

- 同方案 A，但使用浅色排版；下载卡是白底 + 细边框 + 真实版本信息。

**⑥ 页尾**

- 一整块浅灰留白，只有一句 `把显示器，调成你想要的样子。` 和下载按钮。

### 5.3 文案草案

```
页眉    光魂 Center · v1.3
H1      全新升级 Center
副文案  专业调校，回到直觉。

对比段  看得见的改变
        同一块屏，调之前和调之后。

参数段  每一个参数，都有刻度。

联动段  一个进程，一套预设。
        游戏进入前台，模式自己切。

开机段  开机就在，不用重设。

固件段  固件升级，交给它。
        下载、校验、安装，失败可以重来。

页尾    把显示器，调成你想要的样子。
```

### 5.4 技术要点

- 窗口：真实截图 + CSS 3D；浅色背景用多层柔和径向渐变，不用图片。
- 对比滑杆：原生 `<input type=range>` 控制 `clip-path`，键盘可用；
- 参数特写：一个真实的六轴面板（DOM 重建），滑条值与测试图滤镜联动；
- 镜头推进：`sticky` + `scale`，推进时对截图做轻微模糊过渡，避免像素放大发虚；
- 性能：浅色页面没有 WebGL，首屏更轻；所有截图走 `loading="lazy"`。

## 六、两套方案对比

| 维度 | A 穹顶 | B 校准台 |
|---|---|---|
| 气质 | 电影感、深空、沉浸 | 工作室、精密、克制 |
| 主色 | 深海军蓝 + 冷光 | 暖白 + 墨黑 + 品牌蓝 |
| 记忆点 | 弧形穹顶 + 3D 界面拆层 | 前后对比滑杆 + 参数特写 |
| 动效强度 | 强（3 个 pinned 镜头） | 中（2 个 pinned 镜头） |
| 真实感 | 高（真实截图 + 光影） | 高（真实截图 + 测量感） |
| 开发风险 | 中高（WebGL + 3D 分层） | 中（CSS 3D + 对比交互） |
| 移动端 | 需降级为静态角度 | 更容易适配 |
| 适合 | 想让人记住「这是一款很酷的软件」 | 想让人相信「这是一款很专业的软件」 |

## 七、我的建议

如果只选一套：**A 穹顶**更适合这次「全新升级」的发布，因为它有明确的视觉记忆点，也最接近你给的灵感图。

如果希望兼顾专业可信：**A 的首屏 + B 的前后对比段**。首屏用穹顶建立气质，第二屏用可拖动的校准对比证明价值，后面的模块保持安静。

## 八、执行顺序（确认方案后）

1. 生成 6 个导航页的真实截图（2×，WebP），建立资产管线；
2. 先做首屏：穹顶着色器 + 真实窗口 + 3D 归正 + 老虎机数字；
3. 再做第一个 pinned 镜头（拆层或前后对比）；
4. 补三章功能与下载/FAQ；
5. 移动端、旧内核降级、性能与无障碍验收。
