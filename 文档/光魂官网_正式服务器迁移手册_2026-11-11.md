# 光魂官网 · 正式服务器迁移手册

> 适用：把当前测试机（`8.163.108.144`，端口 3002）上验证通过的官网，迁移到公司自有阿里云 ECS（`xxrsm.com` 所在服务器）。
> 原则：**旧站不停、先并行验证、再秒级切换、随时可回滚。**
> 本文所有命令均以 root 执行；尖括号 `<...>` 为需要替换的值。

---

## 0. 迁移前需要拿到的信息

| 项 | 说明 | 是否已确认 |
|---|---|---|
| 正式服务器公网 IP | 域名当前指向的机器 | ☐ |
| SSH 端口 / 账号 / 密钥 | 建议单独开部署账号，不用 root 日常登录 | ☐ |
| 现有 Nginx 配置位置 | 通常 `/etc/nginx/sites-enabled/` 或 `/etc/nginx/conf.d/` | ☐ |
| 旧站代码/静态目录 | 切换后保留，用于回滚 | ☐ |
| 现有 HTTPS 证书 | 是否已有 `xxrsm.com` 证书及路径 | ☐ |
| 端口占用 | 3002 / 3003 是否空闲（商城占用 3001） | ☐ |
| Node 版本 | 必须 22.5+（项目使用 `node:sqlite`） | ☐ |

## 1. 正式服务器体检（只读）

把部署包解压后执行：

```bash
tar -xzf website-*.tar.gz -C /tmp
bash /tmp/website/deploy/preflight.sh
```

检查项：系统、Node 22.5+、npm、`www-data`、3002/3003 端口、同名 systemd 服务、Nginx 配置与 `xxrsm.com` server 块、磁盘、时间同步。

- 有 `[FAIL]`：先处理，不要继续
- `[WARN]`：逐条确认，尤其是「端口被占用」和「xxrsm.com 不在 Nginx 配置里」

> 若 Node 版本不足：
> ```bash
> curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
> apt-get install -y nodejs
> ```

## 3. 部署新站（旧站保持运行）

```bash
# 正式机
rm -rf /tmp/website && tar -xzf /tmp/website-<时间戳>.tar.gz -C /tmp
cd /tmp/website

# 首次部署：端口、站点地址、HTTPS 一次性写对
PORT=3002 \
SITE_ORIGIN=https://xxrsm.com \
COOKIE_SECURE=1 \
TRUST_PROXY=1 \
bash deploy/install.sh
```

脚本行为：

1. 备份旧代码到 `/opt/website/backups/app-*.tar.gz`
2. 升级前对已有数据库做一致性快照
3. 同步代码到 `/opt/website/app`
4. 首次生成 `.env`（随机后台口令），并按上面的环境变量覆盖 `PORT/SITE_ORIGIN/COOKIE_SECURE/TRUST_PROXY`
5. 收紧权限（数据/上传/备份 750，数据库/`.env` 640）
6. 注册并启动 `website.service`、每日备份定时器
7. 健康检查 `http://127.0.0.1:<PORT>/healthz`

**此时旧站完全不受影响**，新站只在服务器本地端口上跑。

### 3.1 导入数据

```bash
systemctl stop website
tar -xzf /tmp/migrate-data-*.tar.gz -C /opt/website/data
chown -R www-data:www-data /opt/website/data
systemctl start website
curl -fsS http://127.0.0.1:3002/healthz
```

导入后用测试机的后台口令登录 `/admin`，**立即修改管理员密码**。

### 3.2 本机验证（切换前必做）

```bash
curl -fsS http://127.0.0.1:3002/healthz
curl -s http://127.0.0.1:3002/ | head -20
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:3002/api/downloads
curl -s -o /dev/null -w '%{http_code}\n' -H 'Host: xxrsm.com' http://127.0.0.1:3002/
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:3002/h-col-160.html
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:3002/b2b.html   # 应为 301
```

## 4. Nginx 切换（控制台操作，窗口约 10 秒）

### 4.0 先备份

```bash
TS=$(date +%Y%m%d-%H%M%S)
cp -a /etc/nginx "/root/nginx-backup-$TS"
tar -czf "/root/old-site-$TS.tar.gz" -C <旧站根目录> . 2>/dev/null || true
nginx -T > "/root/nginx-dump-$TS.conf"
```

### 4.1 现状 A：旧站是静态目录（`root ...`）

把 `xxrsm.com` 的 server 块改为全部反代到新站，避免混用静态与 API：

```nginx
server {
    listen 80;
    listen 443 ssl http2;
    server_name xxrsm.com www.xxrsm.com;

    # 保留原有证书路径
    ssl_certificate     <原证书路径>;
    ssl_certificate_key <原证书私钥路径>;

    client_max_body_size 12m;
    proxy_buffering off;

    location / {
        proxy_pass http://127.0.0.1:3002;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

### 4.2 现状 B：旧站已经是反代（`proxy_pass http://127.0.0.1:<旧端口>`）

只改一行：

```nginx
proxy_pass http://127.0.0.1:3002;
```

### 4.3 生效与回滚

```bash
nginx -t && systemctl reload nginx
curl -s -o /dev/null -w '%{http_code}\n' https://xxrsm.com/
```

若 5 秒内未恢复：立刻 `cp -a /root/nginx-backup-<TS>/. /etc/nginx/`，再 `nginx -t && systemctl reload nginx`。

> 建议把旧 server 块整体注释保留，不要直接删除；Nginx 同一端口不允许两个 `server_name` 相同的块。

## 5. HTTPS

- **已有证书**：直接沿用原 `ssl_certificate` 路径，切换不中断。
- **没有证书**：
  ```bash
  apt-get install -y certbot python3-certbot-nginx
  certbot --nginx -d xxrsm.com -d www.xxrsm.com --redirect
  ```
  证书自动续期由 `certbot.timer` 负责，`systemctl list-timers certbot.timer` 确认。

## 7. 回滚

```bash
# 1) 回滚 Nginx（秒级，优先）
cp -a /root/nginx-backup-<TS>/. /etc/nginx/ && nginx -t && systemctl reload nginx

# 2) 回滚应用代码
bash /opt/website/app/deploy/rollback.sh /opt/website/backups/app-<TS>.tar.gz

# 3) 回滚数据库（仅在数据异常时）
systemctl stop website
cp /opt/website/data/backups/gh-<TS>.sqlite /opt/website/data/gh.sqlite
chown www-data:www-data /opt/website/data/gh.sqlite
systemctl start website
```

## 9. 备份与收尾

1. **每日数据库备份**已由 `website-backup.timer` 自动执行（03:30，保留 7 日 + 4 周）
2. 异地副本二选一：
   - 阿里云 OSS：每天备份后上传，需要桶名 + 只写该桶的 RAM 子账号 AK
   - 本地/NAS：每周把最新 `gh-*.sqlite` 下载一份
3. 每月做一次恢复演练：`sqlite3 gh-*.sqlite 'PRAGMA integrity_check;'`
4. 安全组只保留 80/443；**3002 不对公网开放**
5. 旧站目录、Nginx 备份保留 2 周后再清理
