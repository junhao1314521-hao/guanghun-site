## 一、接口层现状与切换方式

**单一真源**：`/workspace/gh-web/src/api/client.ts`

```
ApiError(message, status=500)                     // 统一错误类型，页面据此区分「失败」与「空」
type ApiRequest = { path; method?; query?; body? }// 请求描述：据此发起真实请求
type Transport = <T>(request: ApiRequest, mockResolve: () => T) => Promise<T>

createHttpTransport(baseUrl): Transport           // 真实 HTTP 传输器：fetch + 状态 → ApiError
export const transport = createHttpTransport(VITE_API_BASE)  // 强制注入 VITE_API_BASE（未注入即报错）
```

> **v4 · M4 演示代码清理（✅ 本轮已完成）**：`getDemoMode` / `demoVariant` / `mockTransport` / `OVERSIZE_*` 演示数据与 `?demo=` 开关（含 `sessionStorage` 记忆）**已全部删除**。`client.ts` 不再保留 mock 传输器；未注入 `VITE_API_BASE` 时在模块加载期抛出明确错误，杜绝「静默空白页」。

**取数链路（唯一形态）**：资源函数 → `transport({ path, query })` → `createHttpTransport` 发起真实 `fetch`。**所有页面数据均来自后端接口，无本地 mock 兜底。**

**环境注入**：
- 本地开发：`.env.development` 已内置 `VITE_API_BASE=http://localhost:8787`（需先启动 `gh-server`）；
- 生产构建：**不读取** `.env.development`，须在部署环境显式注入 `VITE_API_BASE=https://<后端域名>`。

**上线切换步骤**：

1. 构建期注入 `VITE_API_BASE=https://<后端域名>`；
2. 各资源函数 `path`（`/api/products`、`/api/products/:id`、`/api/search`、`/api/ladder` 等）与后端路由对齐（✅ 已完成，见 §二）；
3. 删除演示用途 → ✅ **已完成**（本轮 M4 清理，详见上条 v4 说明）。

**真实传输器已实现**（`createHttpTransport`，`client.ts`）：

- 按 `request.path` + `query` 组装 URL，`method`/`body` 透传；
- 非 2xx → `throw new ApiError(msg, res.status)`，404 语义保持一致；
- 网络失败 → `ApiError(msg, 0)`，页面按错误态展示重试；
- **已实证**：将 `VITE_API_BASE` 指向不可达地址构建后，产品页真实发出 `GET /api/products` 并正确落到组件级错误态（标题「产品加载失败」+「重新加载」），证明切换链路真实有效。

**已完成**：`AbortSignal` 端到端透传（`Transport` → 13 个资源函数 → `useApi` → 页面），切页 / 依赖变化时中止在途请求；主动取消不暴露为错误态。

> `useApi` 三态（loading / error / data）与页面 UI 已就绪，无需改动。

**前后端分工（前端已实现）**：产品筛选/排序、搜索类型筛选/排序、榜单指标切换均在**前端**对返回结果完成，接口只需返回数据集与其元信息。

### 四·B 前端图片/图形占位（替换目标：单一真源 `gh-web/src/data/media.ts`）

> **实现改为集中式占位层（2026-10-11 更新）**：远端出图服务在本环境对所有 prompt 均返回同一张「生成中」占位（md5 一致），不可用于交付。因此**图片占位统一收敛到单一真源 [`gh-web/src/data/media.ts`](../gh-web/src/data/media.ts)**：导出一个 `MEDIA` 映射（hero / heroProduct / scene / product / views / center / about / businessCase），值为**本地确定性 SVG 的 data URI**（暗色影棚基调 + 产品剪影 / 场景透视 / 软件界面 / 品牌光带 / 舞台汇聚）。
>
> - 渲染入口：统一图片组件 `MediaImg`（[`MediaImg.tsx`](../gh-web/src/components/ui/MediaImg.tsx)），失败时回退矢量图，杜绝破图；
> - 尺寸：由容器 CSS + `object-fit` 控制（见 `site.css` 「素材图位」段），撑满不变形；
> - **交付风格描述（2026-10-11 更新）**：`MEDIA` 每个视觉位都带一条**风格规格描述**，写入占位 SVG 的 `<title>`（自解释、可访问）。格式统一为
>   `交付物｜主体｜构图｜光线｜色调｜背景｜比例`，一行讲清最终素材该怎么拍 / 怎么出图，**可直接作为拍摄 / 设计 / 采购的替换依据**，不必再逐位口头对齐。
> - **上线替换：只需把 `MEDIA` 各键的值换成正式素材地址（CDN / 自有静态资源），组件无需改动**；或改由后端接口返回图片字段（如 `Product.image`）。
