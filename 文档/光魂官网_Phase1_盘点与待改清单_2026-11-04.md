### R-04 账号体系 / 找回密码 —— A 类（需选通道）

**现状证据**

- 注册、登录、会话、退出、错误提示均可用；密码错误返回 401 与中文提示。
- 找回密码接口 `POST /api/auth/forgot` 存在，会生成一次性重置令牌。
- **生产环境不返回令牌、也没有邮件/短信通道**：用户点“找回密码”后收不到任何东西，等于不可用。

**缺口**：缺发送通道。

> **执行结果（2026-11-04 已预留通道能力）**：新增 `gh-server/src/lib/notify.ts`，把「生成令牌」与「怎么发出去」解耦。
> 通道由环境变量决定，**未开通时保持现状**（非生产直出 `devToken` 便于自测；生产只写告警日志、响应与已发送一致，不泄露邮箱是否注册）。
> 开通短信或邮件后，只需在 `/opt/website/app/.env` 填四项，**不改代码、不发版**：
>
> ```env
> NOTIFY_CHANNEL=webhook
> NOTIFY_WEBHOOK_URL=https://<你的短信/邮件网关>
> NOTIFY_WEBHOOK_TOKEN=<可选，Bearer 鉴权>
> NOTIFY_TIMEOUT_MS=8000
> ```
>
> 网关收到 `POST { to, subject, text, purpose:"password-reset", at }`：短信通道取 `text` 里的令牌套模板，邮件通道取 `subject` + `text`。
> 阿里云 / 腾讯云短信都可以用一个云函数（或任意中转服务）包一层 HTTP 接口，这就是「等我们有了直接设置」的落点。
> 已补两条测试：生产未配置通道不回传令牌；配置 webhook 后真实投递且响应不含令牌。后端 183 项测试通过，已部署到 3002。

**你需要提供**（二选一，之后我来配）：

| 方案 | 需要你提供 | 特点 |
|---|---|---|
| 企业邮箱 SMTP | 发件邮箱、SMTP 地址、端口、授权码 | 成本低，可能进垃圾箱 |
| 短信服务 | 阿里云/腾讯云短信签名与模板 + 网关地址 | 到达率高，按条计费 |

> 注：当前找回入口是**邮箱**，短信找回需要先有「手机号绑定 + 按手机号查账号」。`users.phone` 字段已预留，等你确定短信方案后我再补这条链路。

**我拿到后的动作**：填环境变量 → 重启 `website` → 令牌邮件/短信 → 重置页 → 全流程实测（含过期令牌）。

### R-05 素材上传基础 —— 部分达标（进度已补 2026-11-04）

**现状证据**

- 图片 10MB / 文档 50MB / 视频 200MB 分档限制，可按环境变量覆盖。
- 超出限额返回中文原因；支持素材库多选、排序、替换。
- 图片上传会生成尺寸变体（srcset）。
- **安装包（exe / dmg / msi）不在素材库白名单**，后台字段提示“请填对象存储 / CDN 外链”。
- 上传改用 XHR：素材库「上传素材」按钮与区块图片字段均显示实时百分比（`上传中 42%`）。

**瓶颈与结论（200MB 是否算大）**

- 测试服为 `ecs.e-c1m1.large`（2 vCPU / 1.7GB 内存 / 34GB 磁盘 / 无 swap），公网带宽为经济型实例常见档位。
- 200MB 文件**下载**在 5Mbps 下约需 5.5 分钟、1Mbps 下约 28 分钟，多人同时下载会互相挤占——这是主要瓶颈，不是磁盘。
- 上传侧：服务端用 `express.raw` 整体缓冲请求体，200MB 单次上传会占用等量内存，2 个并发即有 OOM 风险。
- **结论**：≤50MB 的 zip / rar / 7z / bin 直传服务器；exe / dmg / msi 与 >50MB 安装包统一放对象存储 + CDN，后台只存外链与 SHA-256 校验值。

**仍待改**

1. 安装包直传（需对象存储 + 分片/流式上传），当前走外链。
2. 大文件（>50MB）无断点续传。
3. 批量上传只有逐个文件的百分比，没有整体队列汇总。

### R-06 发布链路 —— B 类（已完成 2026-11-04）

**原缺口**

1. 编辑中的内容会立刻影响线上，无法“先改好、再发布”。
2. 定时发布是“到点应用快照”，但编辑期间线上已经变了，语义容易误解。
3. 没有“预览未发布版本”的入口。

**已实施（schema v9）**

- 新增 `content_drafts(key, data, updated_at)`：后台「保存草稿」只写草稿表，前台仍读 `content_pages`，线上不再被编辑动作影响。
- 新增 `POST /api/admin/pages/:key/publish`：草稿覆盖线上并删除草稿；`DELETE /api/admin/pages/:key/draft` 放弃草稿。
- `GET /api/admin/pages` 与 `GET /api/admin/pages/:key` 回传 `hasDraft / draftUpdatedAt`，后台列表显示「有草稿」标记、装修器顶栏显示「有未发布变更」，并出现「放弃草稿」按钮。
- 全局「发布」(`POST /api/admin/publish`) 改为：**先把所有草稿覆盖到线上，再生成版本快照**，保证快照就是本次上线后的内容。
- 预览：装修器右栏实时渲染当前草稿（含未保存状态），保存后从服务端载入草稿继续预览，因此“预览未发布版本”已在编辑器内闭环。
- 「重置为初始」保持立即生效语义，并同时清除草稿；删除页面 / 重置整站也会清理对应草稿，避免孤儿数据。

**线上验收证据（8.163.108.144:3002）**

- 保存草稿后：`/api/content/pages/brand-lab` 仍返回旧标题；后台列表 `hasDraft=true`。
- 发布后：前台标题更新为新值，`hasDraft=false`，草稿表清空。
- 回归：后端 181 项测试、前端 44 项测试全部通过；`schema_version=9`。

**仍可增强（非阻塞）**：带签名的“游客可看”预览链接（当前预览需登录后台）。
