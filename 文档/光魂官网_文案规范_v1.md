## 1. 语气原则

1. **事实优先**：先给参数、方法、范围或下一步，再给判断；形容词只作补充，不承担信息。
2. **短句**：一句只表达一个意思；标题不超过两行，说明不超过三句。
3. **可核对**：每个数字、承诺、结论都应能对应产品参数、测试方法、售后条款或公开文件；对不上就不写。
4. **平静的专业感**：不喊口号、不制造焦虑、不用感叹号；不写"我们深知""在这个时代"这类铺垫。
5. **一致**：同一事物在全站用同一个词；按钮文案与实际去向一致。

## 3. 禁用与慎用

**禁用（无实测或事实支撑时）**：极致、至尊、颠覆、震撼、畅享、引领、赋能、无限、黑科技、重新定义、全新升级、王者、天花板、平民超跑、八面出锋、大巧不工。

**慎用**：沉浸、专业、稳定、高效、领先。使用前必须补上具体条件，例如"在 2K@540Hz 下""按公开测试方法"；补不上就删。

**禁止的数字写法**：无来源的百分比、倍数、售罄时长、覆盖数量、"累计服务 N 人"。"以官方公布为准"只能用于确有待公布事项，不能用来兜底编造。

## 5. 状态文案

- **错误**：说明发生了什么 + 用户可执行的动作。例："壁纸加载失败，请检查网络后重试。"按钮"重新加载"。
- **空态**：说明当前没有什么 + 如何产生或下一步。例："暂无可展示的产品。"不写"敬请期待"。
- **表单失败**：保留已填内容，明确"可稍后重试"。
- **成功**：只陈述结果，不夸张。例："已复制 4K 图片链接"。

## 6. 数据状态与来源（2026-11-21 生效）

没有真实数据时，不再靠"以官方公布为准"兜底，按以下三层处理：

1. **标注**：每个区块在后台有「数据状态 / 数据来源」两个字段（`dataStatus` / `dataSource`）。
   - `待补`：暂无真实来源；
   - `已核对`：必须填写来源（产品库、测试记录编号、合同或官方文件）；
   - 未标注：视为尚未核对。
2. **前台降级**：标记 `待补` 的区块，前台自动隐藏该区块内带 `data-metric` 的数字与未核实承诺，只保留标题、说明与操作；不出现"数据待补充"占位。
3. **可见性**：装修器区块列表显示「数据待补」角标；「立即发布」弹窗列出待确认条目（只提示，不阻断）。

审计自动识别的两类内容：承诺词（包邮 / 现货速发 / 无理由 / 售罄 / 好评率 / 销量）与带单位的效果数字（倍 / % / 小时 / 分钟 / 所 / 个 / 款 / 人次）。产品参数（Hz、ms、nit、Gbps、英寸）与功能规则（"选择最多 4 款"）不误报。

写作时的判断顺序：能给出来源 → 写数字并标 `已核对`；给不出来 → 改写成范围 / 动作 / 条件的定性描述；连定性描述都无法核对 → 标记 `待补`，由前台隐藏该项。
