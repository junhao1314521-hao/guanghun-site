## 1. 本轮原则

1. **完全体标准**：按真实用户与真实运营人员使用，不以「演示能跑」为准。
2. **禁止假功能**：下载、账号、发布、地图、二维码等必须有真实数据与真实链路。
3. **先可视化后实现**：涉及新页面或大改版（网点页、Center、客服组件）先出可点击原型，确认后再写正式代码。
4. **一次一个阶段**：每阶段独立验收，避免跨阶段混改导致回归难定位。
5. **不破坏线上**：所有改动先在本地验证，再部署 3002；数据库改动必须先备份。
6. **Center 延后**：等其余阶段完成、收到安装程序后再单独做（Phase 6）。

### 1.1 已确认业务口径（2026-11-04）

- **官网不自建交易**：不加入购物车、下单、支付、订单、售后；所有成交走天猫 / 京东 / 抖音 / 小程序商城。
- **购买链接按产品独立配置**：后台每个产品填自己的外链，运营可按阶段换成天猫、京东、抖音或小程序链接。
- **无购买链接时回退**：显示「预约体验」或「提交咨询」，不出现死链。
- **体验点联动**：若产品在体验点有陈列，产品详情提供「预约体验」入口，跳转网点页并尽量按产品筛选/定位。
- **联系方式**：当前占位保留，待整体优化完成后统一替换为真实热线、邮箱、地址、备案号。

## 3. 阶段计划

### Phase 0 · 盘点与基线（不改线上）

- 输出：问题清单（P0–P3）+ 证据（URL/截图/复现步骤）+ 建议修复阶段
- 门禁：需求清单确认后才进入 Phase 1

**状态（2026-11-04）**：盘点已完成，产出 `光魂官网_Phase0_盘点和问题清单_2026-11-04.md`。
结论：框架与后台能力较完整，但下载真实性、产品卡图、购买入口、联系方式等 P0 项阻塞上架；移动端 320/390/430 设备矩阵待 Phase 2 补测。

- 下载中心真实化；产品上架数据与详情；账号全流程；上传基础；发布/回滚；安全与运维；手机端关键路径
