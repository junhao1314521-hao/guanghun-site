# 光魂官网 · 内容库与装修契约 v1.0

> 本文件是「后台装修系统 + 前台内容驱动」的唯一真源（single source of truth）。
> 前后端类型、API、区块字段、页面 registry 均以本文件为准；实现偏离即为缺陷。
> 版本：v1.0　范围：全打通 + 全页面装修（数据页用数据源区块）+ 进阶编辑

---

## 0. 目标

把后台从「一堆独立数据表」升级为「**一套内容库 + 一个按页面组织的区块装修器**」：

- 前台**内容页**与**数据列表页**全部由内容库中的「页面 → 区块有序列表」驱动渲染；
- 后台改动 → 前台刷新即生效（同源 API，无第二份硬编码内容）；
- 区块可**增 / 删 / 排序 / 启用停用**，区块内**每个字段可编辑**（大到图片，小到标题文字）；
- 数据结构化持久化到磁盘 JSON，服务重启不丢。

## 1. 概念模型

| 概念 | 说明 |
|---|---|
| **区块 Block** | 页面最小可编辑单元，16 类基础区块 + 3 类自定义模块 + 1 类扩展（`showcase`，对齐 PRD REQ-13） |
| **页面 Page** | 一条**有序区块列表** + 元信息，对应一个前台路由 |
| **内容库 Store** | 全部 Page + 站点配置（导航 / 页脚），持久化为 JSON 文件 |
| **数据源区块** | 不存内容，只存「查询参数」（来源 / 数量 / 筛选），渲染时向后端结构化数据取数 |
| **装修区** | 页面下方可装修的区块序列（明细页用，见 §10） |

## 3. 区块通用结构

```ts
export type BlockType =
  | 'hero' | 'carousel' | 'video' | 'text' | 'imageText' | 'imageGrid'
  | 'stats' | 'cards' | 'timeline'
  | 'productGrid' | 'articleList' | 'ranking' | 'downloadList' | 'faqList'
  | 'contact' | 'layout'
  // 自定义模块（§4-附）：富文本 / HTML / 代码嵌入沙箱
  | 'richText' | 'html' | 'embed'
  // 扩展（§4-附）：通栏产品展示（首页「重点产品」分段式）
  | 'showcase'

export type BlockStyle = {
  background?: 'none' | 'soft' | 'solid' | 'gradient'   // 区块底色
  paddingY?: 'sm' | 'md' | 'lg'                          // 上下留白
  align?: 'left' | 'center'                              // 对齐
  theme?: 'auto' | 'light' | 'dark'                      // 强制明暗
  container?: 'wide' | 'normal' | 'narrow' | 'full'       // 内容宽度（full = 通栏/全宽，破出容器铺满视口）
}

export type Block = {
  id: string                    // 稳定唯一 id（前端/后端一致）
  type: BlockType
  enabled: boolean              // 停用则不渲染（前台与预览都跳过）
  props: Record<string, unknown> // 按 §4 类型字段
  style?: BlockStyle
}

export type Page = {
  key: string                   // 页面 key（§2）
  path: string                  // 前台路由（模板页可含 :param）
  title: string                 // 后台显示名
  description?: string
  blocks: Block[]               // 有序
  updatedAt: string             // ISO
}
```

## 5. 页面 registry

- registry 存于内容库（`pages[]`），初始 seed 由现有 `gh-server/src/data/*.ts` 内容映射生成。
- 页面 key 唯一；`path` 用于前台匹配与后台展示。
- 模板页（`template-*`）的 blocks 仅描述**装修区**（明细主体由结构化模板组件渲染）。

## 6. 内容 API 契约

> 全部遵循既有约定：**响应体直接返回数据本身，无 `{code,data}` 包装**；错误为 `{ error: string }`。

### 6.1 公开（前台）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/content/pages` | 页面列表 `{ items: PageMeta[], total }`（不含 blocks） |
| GET | `/api/content/pages/:key` | 单页 `{ page: Page }`；未命中 404 |
| GET | `/api/content/site` | 站点配置 `{ nav, footer, enabledBlocks?, theme? }`（后两者为扩展字段，缺省不返回） |
| GET | `/api/content/blocks/types` | 区块类型目录 `{ items: BlockTypeMeta[] }`（共 26 类，每项含 `enabled` 启用状态） |

### 6.2 后台（需 `Authorization: Bearer <token>`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/admin/pages` | 页面列表 `{ items, total }` |
| GET | `/api/admin/pages/:key` | 单页 `{ page }` |
| PUT | `/api/admin/pages/:key` | 保存整页（blocks 全量覆盖）→ `{ page }`；持久化落盘 |
| POST | `/api/admin/pages` | 新建页面 → `{ page }`（可传 `blocks` 从模板起步） |
| DELETE | `/api/admin/pages/:key` | 删除页面（内置页面禁删）→ `{ ok: true }` |
| POST | `/api/admin/pages/:key/reset` | 重置为 seed → `{ page }` |
| PUT | `/api/admin/site` | 保存站点配置（**浅合并** nav/footer/enabledBlocks/theme）→ `{ site }` |
| PUT | `/api/admin/blocks/enabled` | 保存启用的区块类型 `{ enabled: string[] }` → `{ enabledBlocks }` |
| PUT | `/api/admin/theme` | 保存站点级设计令牌覆盖 `{ theme: Record<string,string> }` → `{ theme }`（白名单外键被过滤） |
| GET | `/api/admin/templates` | 模板列表 `{ items: TemplateItem[], total }` |

**素材库（文件夹 / 分类，后台改造新增）**：均需会话 + scope `content`；响应直出、错误 `{ error }`。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/admin/uploads` | 上传单文件 → `{ item: MediaItem }`（可选 query `folderId` / 头 `X-Folder-Id` 指定目标文件夹；既有行为兼容） |
| POST | `/api/admin/uploads/:id/variants` | 登记主图的尺寸变体（body `{ variants: { width, url, size, type }[] }`，整体替换、幂等）→ `{ item }`；主图未命中 404；缺 `variants` 数组 400 |
| GET | `/api/admin/uploads` | 素材列表 → `{ items: MediaItem[], total }`；query `folderId`（id \| `uncategorized` \| 省略=全部）/ `category` / `q` / `type` / `page` / `pageSize` |
| PATCH | `/api/admin/uploads/:id` | 更新素材元数据（`{ category?, folderId? }`）→ `{ item }`；未命中 404 |
| POST | `/api/admin/uploads/move` | 批量移动（`{ ids: string[], folderId?: string\|null }`）→ `{ ok: true }` |
| DELETE | `/api/admin/uploads/:id` | 删除素材 → `{ ok: true }`；未命中 404 |
| GET | `/api/admin/media/folders` | 文件夹列表 → `{ items: FolderItem[], total, uncategorized }`（含每夹 `fileCount`） |
| POST | `/api/admin/media/folders` | 新建文件夹（`{ name, parentId? }`）→ `{ item }`（201） |
| PATCH / PUT | `/api/admin/media/folders/:id` | 重命名 / 移动（`{ name?, parentId? }`）→ `{ item }`；未命中 404；成环 400 |
| DELETE | `/api/admin/media/folders/:id` | 删除文件夹 → `{ ok: true }`；未命中 404 |

**公开素材端点（无需鉴权）**：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/media/variants?url=/uploads/<文件名>` | 按图片地址查询其尺寸变体 → `{ url, variants: MediaVariant[] }`；未命中 / 非 `/uploads/` 地址 / 无变体均 **200 + 空数组**（供前台 `srcset` 消费，退化为单张） |

```ts
// 尺寸变体（对主图的衍生小图；由浏览器端 Canvas 在上传主图时生成并作为独立文件上传）
export type MediaVariant = { width: number; url: string; size: number; type: string }
// 素材条目（对上传契约 UploadItem 的扩展：新增 folderId / category / variants）
export type MediaCategory = 'image' | 'icon' | 'doc' | 'video' | 'other'  // 图片/图标/文档/视频/其它
export type MediaItem = {
  id: string; name: string; url: string; size: number; type: string; uploadedAt: string
  folderId: string | null        // 所属文件夹 id；null = 未分类
  category: MediaCategory        // 分类（MIME 自动推导，允许 PATCH 手工覆盖）
  variants: MediaVariant[]       // 尺寸变体列表（无变体时为空数组；字段只增不改）
}
export type FolderItem = {
  id: string; name: string; parentId: string | null
  sort: number; createdAt: string; fileCount: number
}
```

> 变体文件作为**独立素材**落盘（沿用 `POST /api/admin/uploads`），但**不出现在素材列表中**（由主图的 `variants` 字段承载），也不计入文件夹 `fileCount`；删除主图时**级联删除**其变体文件与元数据。
> 多尺寸生成策略：位图（png/jpeg/webp）生成 **320 / 640 / 1280** 三档（保持宽高比、按需缩小、不放大原图），输出优先 **WebP**（浏览器支持时），质量 0.8；`image/svg+xml`（矢量）与 `image/gif`（动图）跳过，仅传原图。

> 删除**非空**文件夹策略：其中文件移入「未分类」（`folder_id = NULL`），其子文件夹**上提一层**（不级联删除）。
> 分类自动归类规则：`image/svg+xml` → icon；其余 `image/*` → image；`video/*` → video；pdf / text / zip / office → doc；其余 → other。

## 7. 持久化（SQLite，阶段 5a）

- 存储：**单库 SQLite 文件** `/workspace/gh-server/data/gh.sqlite`（环境变量 `DB_PATH` 可覆盖；启动时目录不存在则创建）。
- 表：
  - `content_pages(key, data, updated_at)`：每个内容页一行（`data` 为 Page 的 JSON）；
  - `site_config(id=1, data)`：站点配置单行（`data` 为 SiteConfig 的 JSON）；
  - `collections(key, id, data, sort)`：结构化集合记录（`sort` 越小越靠前 / 越新）；
  - `admin_resources(key, id, data, sort)`：其余后台资源记录；
  - `audit_log(id, at, actor, action, target, detail, ip, seq)`：审计日志（`seq` 越小越新）；
  - `releases(id, at, actor, note, content_version, block_count, page_count, collection_count, snapshot)`：
    发布记录（`snapshot` 为该次发布的内容快照 JSON，供回滚）；
  - `admin_users(id, username, salt, hash, name, role, scopes, created_at)`：后台账号（`role` 存角色键，`scopes` 冗余存派生权限集）；
  - `upload_folders(id, name, parent_id, sort, created_at)`：素材库虚拟文件夹（后台改造新增，不映射磁盘目录）；
  - `upload_meta(id, folder_id, category, updated_at)`：素材文件元数据（`id` = 磁盘文件名；`folder_id` 为 NULL 表示未分类；`category` 非空时覆盖 MIME 推导）；
  - `upload_variants(main_id, url, width, size, type, sort, updated_at)`：图片尺寸变体元数据（`main_id` = 主图磁盘文件名；`url` = 变体公开地址；主键 `(main_id, url)`）；
  - `metrics_events(id, kind, key, at)`：**轻量埋点事件**（`kind` = `view`（页面浏览）/ `download`（下载点击）；`key` = 页面路径或下载项 id；`at` = ISO 时间）。公开端点 `/api/track/*` 写入；默认保留最近 20000 条（`METRICS_MAX` 可覆盖），`TRACK_ENABLED=0` 关闭。
  - `trash(id, key, record_id, data, deleted_at, deleted_by)`：**回收站**（内容类资源 / 集合记录软删除的落点；`key` = 原栏目 key、`record_id` = 原记录 id、`data` = 原记录 JSON）。恢复 / 彻底删除端点见接口契约 §2.5。
  - `meta(key, value)`：记录 `schema_version`（当前 `5`）与是否已完成迁移（`migrated_json`）。
- 启动：对应表为空时用 seed 生成并写入（内容库 / 站点 / 各集合 / 后台资源）。
- 写入：任一 PUT/POST/DELETE 后**立即在同一事务内落库**（原子性）。
- 并发：`node:sqlite` 同步 API + 事务；`PRAGMA journal_mode=WAL`、`foreign_keys=ON`。
- 迁移：**首次启动**若库为空且存在旧 JSON 文件（`data/content-store.json` / `collection-store.json` /
  `admin-resources.json` / `audit-log.json`）则一次性导入，并在 `meta` 标记已迁移；**旧 JSON 文件不删除**（仅停止写入），留作人工核对 / 回滚。
- 容错：库打开 / 建表失败 → 记结构化日志并抛出明确错误（**不静默降级**）；旧 JSON 损坏 → 跳过迁移、由 seed 承担回退。
- seed 真源：`gh-server/src/data/contentSeed.ts` 与各 `data/*.ts` 模块（不变）。
- 实现：`gh-server/src/data/db.ts`（连接 / 建表 / 迁移；`Store` 模块仅调用它，对外接口签名不变）。

### 11.5 前台会员账号与会话（阶段 5）

> 与后台 `admin_users` / 内存会话 **完全隔离** 的一套；出现在同一 SQLite 单库（`DB_PATH` 可覆盖）。

新增表（`SCHEMA_VERSION` v5 → **v6**）：

| 表 | 字段 | 说明 |
|---|---|---|
| `users` | `id, username(UNIQUE), email(UNIQUE), phone, salt, hash, name, created_at` | 前台会员账号；密码 **scrypt 加盐哈希**（`salt`+64 字节派生密钥，hex），与后台同规格 |

| `user_account_data` | `user_id, section, data, updated_at`（PK `user_id+section`） | 个人中心按用户隔离的数据：`devices` / `favorites` / `notifications`（各存一份 JSON） |

数据归属与隔离：

- **我的咨询**：`inquiries` 集合记录新增可选字段 `userId`；登录用户经 `POST /api/inquiry` 提交时写入其 `userId`，
  `/api/account/inquiries` 仅返回当前用户的记录（访客提交无归属，不进入任何会员的列表）。
- **设备 / 收藏 / 通知 / 基本资料**：按 `user_id` 隔离存于 `user_account_data`（基本资料 name/phone 存于 `users`）。
- **隔离方式**：两套会话各自独立 Cookie（`gh_admin` / `gh_user`）与存储，可并存且互不影响。

`POST /api/auth/register|login|logout`、`GET /api/auth/me`、`POST /api/auth/forgot|reset|password`；
`GET /api/account/me|inquiries|inquiries/:id|devices|favorites|notifications|settings`、`PUT /api/account/notifications|settings`。
