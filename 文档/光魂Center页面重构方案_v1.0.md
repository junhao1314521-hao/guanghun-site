# 光魂 Center 页面重构方案 v1.0

> 目标：把 `/center` 从「软件信息页」升级为「有高级感、有科技感、可交互的产品体验页」。
> 状态：方案待确认。确认后按第八节顺序落地，替换需求池 R-33。

---

## 一、调研结论

### 1.1 参考站拆解

| 参考 | 结构/手法 | 可复用的点 |
|---|---|---|
| Razer Synapse 4 | 首屏「一句话 + 双平台下载（含系统小字）」→ 云版试用 → 性能/稳定性/UI 三组数据化卖点 → 老用户功能 → Beta 通道 | 下载按钮旁固定标注系统版本；用「30% faster」这类可验证数字；给 Beta / 旧版留位置 |
| NVIDIA App | 首屏「See in action」视频 → 分段功能（驱动 / 控制中心 / 录制 / 叠加层 / 滤镜）→ 生态应用 → 支持矩阵（系统要求 / 支持列表 / 更新说明 / FAQ） | 每个功能配一段动图/视频；底部固定四宫格支持入口，减少「找不到」 |
| MSI Center | 场景选择器（Gamer / Creator / 办公…）→ 模块化功能集 → 主题切换演示 → 功能清单 Tab | **场景驱动**：先问「你是谁」，再展示功能；Tab 切换比长列表更易读 |
| Corsair iCUE | 顶部锚点 Tab 导航 → 大图功能区 → 生态伙伴网格 | 顶部锚点 + 滚动高亮，长页面不迷路；生态/兼容性单独成块 |
| 原光魂 control.html | 软件标识卡 + 平台/版本/大小/更新/支持型号 + 立即下载 → 4 张能力卡（基础/电竞/图像/系统）→ 专业面板模拟（色域预设 + 六轴饱和度/色调滑条）→ 状态栏（分辨率/刷新率/色深/预设/HDR/VRR） | **这页最有价值的资产是「专业面板模拟」和「状态栏读数」**——其他品牌都只放截图，我们可以做成真的可交互 |

### 1.2 结论

1. 同行的软件页都在做「截图 + 视频」，**没有一家把软件界面做成可操作的模拟器**。这是我们做出差异化的最大机会。
2. 高级感不靠堆 3D，而靠：**深空底色 + 克制的光 + 精准的排印 + 一处「活的」交互**。
3. 用户第一诉求永远是「下载」，所有炫技不能挡住下载路径：首屏、页中、页尾三次可达。

### 1.3 真实软件拆解（已完成）

安装包 `Center-1.3.3-win64-setup.exe` 为 NSIS 壳 + **Tauri 2** 应用。Linux 沙箱无法运行 Windows/WebView2 程序，改为解包安装器并提取 Tauri 内嵌的完整前端：

- 已提取：`index.html`、CSS 114 KB、JS 555 KB、`logo.png`、Rajdhani / JetBrains Mono / Noto Sans SC 字体
- 已用 Chromium 真实渲染并截图：`/workspace/.screenshots/center-app/01-basic.png`
- 真实品牌色：`#3B82F6`（primary-500）/ `#2563EB`（600），与官网现有品牌蓝一致
- 真实框架：窗口圆角 2rem、260px 侧栏、毛玻璃面板、Rajdhani 数字字体、等宽读数
- 真实导航（6 项）：基本功能 / 电竞设置 / 专业设置 / 图像调节 / 输入源 / 系统设置
- 真实控件：亮度、对比度、预设模式（标准 / E-SPORTS / FPS / RTS / MAC / 低蓝光 / 玩家1 / 玩家2）、暗部增强、色彩增强、双模切换、清晰度、辅助准心（准心1–4 + 四角位置 + 缩放）、刷新率显示、色域空间、色温（暖色温1/2、冷色温1/2、自定义）、伽马、RGB 增益、六轴饱和度 / 色调、灯效（白色 / 呼吸 / 流水）、音量 / 静音、恢复出厂
- 真实状态栏：分辨率、刷新率、色深、预设模式、HDR、VRR、画面带宽 / 接口带宽
- 隐藏但真实的能力：应用联动（App-Link Sync，按进程自动切模式）、固件 OTA、多显示器切换、工程模式（白名单 + VCP 日志，营销页不展示）

结论：模拟器不再靠想象，**按真实界面 1:1 复刻**，控件名称、取值、预设名全部对齐软件。

## 二、原页面信息资产盘点

原页可直接继承的内容：

- 软件标识：SVDC / CENTER、Logo（`/brand/svdc.svg`）
- 元信息：平台 Windows 10/11、版本、大小、更新日期、支持型号
- 能力四分类：基础功能（亮度/对比/色温/Gamma/蓝光/DCR/HDR）、电竞设置（FreeSync/VRR+/准星/帧数/暗部/OD）、图像调节（PBP/PIP/比例/锐度/动态亮度/镜像）、系统设置（OSD 语言/按键映射/USB KVM/固件 OTA/恢复出厂/设备识别）
- 专业面板：色域预设（预设 / sRGB / DCI-P3）、六轴饱和度、六轴色调
- 实时状态栏：分辨率 / 刷新率 / 色深 / 预设模式 / HDR / VRR+

原页的问题：

- 首屏是「静态标识卡」，没有产品感；
- 功能是 4 个平铺列表，没有主次，也没有「这个功能解决什么问题」；
- 专业面板只是静态截图式排版，滑条不可动，无法体现软件价值；
- 缺少场景、设备兼容、安装引导、更新日志的叙事顺序；
- 整页只有 1 个下载入口，且埋在首屏底部。

## 三、定位与设计原则

**一句话定位**：把显示器的专业调校，变成一个能用鼠标完成的界面。

五条设计原则：

1. **一屏一个主张**：每个屏只讲一件事，标题就是结论。
2. **真实优先**：版本、大小、日期、支持型号全部取下载中心真实数据，不写假数字。
3. **交互必须有意义**：滑条动了，预览画面就要跟着变；不能只为动而动。
4. **性能是高级感的一部分**：不引入 3D 引擎，全部用 CSS transform / opacity + Canvas 2D。
5. **可降级**：`prefers-reduced-motion`、触屏、低端机都有静态版本。

## 四、页面结构（9 屏）

### 屏 1 · 首屏 Hero（全屏）

- 背景：**不用任何图片**，纯代码生成。Canvas 2D 绘制深空星场（≤160 点，DPR≤2，页面隐藏时暂停）+ CSS 渐变地平线辉光 + SVG 细网格（24px，径向遮罩）+ 噪点；三层以不同速率响应滚动，形成视差。首屏不再依赖 `hero-space.jpg`。
- 左侧文案：
  - 眉题 `SVDC CENTER · 显示器控制中心`
  - 主标题 `把显示器的控制权，交还给你。`
  - 副文案 `一处调完亮度、色彩、刷新率与固件，不用再摸显示器背后的按键。`
  - 元信息行：`Windows 10/11` · `v1.3.3` · `4.5 MB` · `2026-11-05`
  - 主按钮 `下载 Windows 版` + 次按钮 `查看更新日志`
- 右侧：**软件窗口实体化**——一块 16:10 的深色玻璃面板，内含模拟 Center 界面（左导航 + 参数卡），带顶部高光、底部反光、外发光。
- 滚动联动：窗口初始 `rotateX(8deg) rotateY(-6deg)`，随滚动归正并轻微上浮；文案层视差 0.15x。
- 移动端：窗口降为文案下方一张静态卡片，关闭视差。

### 屏 2 · 能力总览（六模块）

- 标题：`六件事，一个窗口做完`
- 布局：3×2 交互卡片（显示 / 色彩 / 电竞 / 图像 / 设备 / 更新）。
- 交互：悬停时卡片边框出现沿边流光，图标轻微浮起，右侧浮出该模块的一句话价值（不用点开）。
- 每张卡右下角 `→` 锚点，跳到屏 3 对应 Tab。

### 屏 3 · 交互式控制台（核心差异点）

一整块仿软件界面的「可操作 Demo」，框内标注 `功能示意，非当前设备实时状态`。

- 左侧导航：与真实软件完全一致的 6 项 —— `基本功能` `电竞设置` `专业设置` `图像调节` `输入源` `系统设置`
- 右侧内容随 Tab 切换：
  - **基本功能**：显示器型号、分辨率 / 刷新率 / 方向、亮度 / 对比度、预设模式（标准 / E-SPORTS / FPS / RTS / MAC / 低蓝光 / 玩家1 / 玩家2）
  - **电竞设置**：暗部增强、色彩增强、清晰度、辅助准心（准心1–4 + 四角位置 + 缩放尺寸）、刷新率显示、双模切换、VRR
  - **专业设置**：色域空间、色温（暖色温1/2、冷色温1/2、自定义）、伽马、六轴饱和度、六轴色调
  - **图像调节**：HDR、DSC、RGB 增益、动态亮度、画面比例、PBP / PIP
  - **输入源**：DP / HDMI / USB-C / 自动切换（真实软件为 VCP 96）
  - **系统设置**：灯效（白色 / 呼吸 / 流水）、显示器语言、音量 / 静音、恢复出厂
- **联动效果**：右侧预览区是一块示意画面，滑条变化实时映射为 CSS `filter: brightness/contrast/saturate/hue-rotate`；HDR 开关切换一层高光渐变；准星开关在预览区叠加十字线。
- 底部状态栏：分辨率 / 刷新率 / 色深 / 预设模式 / HDR 状态 / VRR / 画面带宽与接口带宽（与真实软件一致，随操作实时变化）。
- 交互约束：不用真实硬件，全部前端状态；首次进入自动演示一次（2 秒内完成一组参数变化），用户操作后停止自动演示；明确标注「功能示意」。

### 屏 4 · 一键场景

- 标题：`不用懂参数，也知道该选哪个`
- 三张场景卡：`对战` `创作` `办公`。
- 点击后：屏 3 的模拟器参数、预览画面、背景光晕色温同步切换（对战偏冷蓝、创作偏中性、办公偏暖）。
- 卡片显示该场景的关键设置摘要（如对战：`OD 强 · 暗部增强 +2 · 准星开 · 280Hz`）。
- 这是「场景驱动」（MSI 的做法）与「可交互模拟器」的结合。

### 屏 5 · 功能深读（Sticky 滚动叙事）

左侧文案固定（sticky），右侧三张界面截图/动图随滚动切换：

1. `调校不再是玄学` — 参数口径与天梯榜测试一致，改完可一键还原。
2. `固件更新不用找教程` — 检测、下载、校验、回滚一条链路。
3. `换台电脑，配置还在` — 账号同步，本地与云端各留一份。

移动端：改为三张上下排列的图文卡，不做 sticky。

### 屏 6 · 支持的设备

- 标题：`连上就能认出来`
- 型号 chip 网格，按系列分组（OLED 旗舰 / 双模高刷 / 待支持），支持站内搜索过滤。
- 每行显示：系列名 + 型号列表 + 状态标签（全面支持 / 部分支持 / 规划中）。
- 数据来源：`DEVICE_SUPPORT`（需研发确认最终清单）。

### 屏 7 · 下载与安装

- 左侧版本卡：版本号、日期、大小、系统要求、SHA256（可选）、`下载 Windows 版`。
- 右侧三步：下载安装 → 连接显示器 → 自动识别。
- 下方补充：`暂不提供 macOS 版本`、`更新日志` 锚点、`安装遇到问题？` 咨询入口。
- 下载按钮统一走下载中心真实条目（`center-win`），不写死链接。

### 屏 8 · 更新日志

- 竖向时间线，默认展开最近 3 条，其余折叠。
- 每条：版本号 + 日期 + 一句话变更 + 可选「查看详情」。

### 屏 9 · FAQ + 页尾 CTA

- FAQ 5 条（沿用现有 + 新增「模拟器是否为真实设备状态」）。
- 页尾：深空渐变 + 一句话 + 下载按钮，形成第三次下载入口。

## 五、视觉系统

| 项 | 方案 |
|---|---|
| 底色 | `#05070D → #0A1020` 深空渐变，局部 `#101828` 面板 |
| 主色 | 沿用品牌蓝 `#3B82F6`，辅色青 `#38BDF8`，紫 `#7C5CFF` 只用于光晕，不用于文字 |
| 文字 | 标题白色 90%，正文 `#A8B0C0`（对比度 ≥ 4.5:1），弱化 `#6B7488` |
| 质感 | 玻璃面板（模糊 18px + 1px 内高光 + 外发光）、细网格（24px）、噪点（3% 透明度） |
| 数据 | 所有读数、版本号、参数值用等宽字体（`ui-monospace`），带单位小字 |
| 圆角 | 面板 20px，卡片 16px，按钮 999px（与现有站点一致） |

动效清单：

- 入场：文案逐行 40ms 错峰；窗口 600ms 归正 + 光晕呼吸一次。
- 滚动：首屏视差、屏 5 sticky 切换、数字 count-up（只播放一次）。
- 悬停：卡片流光描边、图标 2px 上浮、按钮高光扫过。
- 全部动效 `prefers-reduced-motion: reduce` 时降为静态。

## 六、技术实现

### 6.1 架构选择

现状 `/center` 完全由内容库区块驱动（`PageView`），无法承载跨区块联动状态。

| 方案 | 说明 | 结论 |
|---|---|---|
| A 纯自定义页面 | `CenterPage.tsx` 自写全部结构与样式，文案走常量 | 效果最好，后台不可改结构 |
| B 新增专用区块 | 新增 `centerHero` / `centerSimulator` / `centerScenes` 三种 block | 后台可排序，开发量最大，联动状态跨区块难做 |
| **C 混合（推荐）** | 页面骨架自定义；首屏文案、下载条目、更新日志、FAQ 仍从内容库 / 下载中心读取 | 兼顾效果与可维护性 |

推荐 C：

- 新建 `gh-web/src/pages/CenterPage.tsx` + `gh-web/src/styles/center.css`（或同目录 CSS）
- 页面内拆分：`CenterHero` / `CenterCapabilities` / `CenterConsole` / `CenterScenes` / `CenterFeatures` / `CenterDevices` / `CenterDownload` / `CenterChangelog` / `CenterFaq`
- 数据：`api/support-extra.ts` 的 `fetchDownloads` 取真实版本；文案常量放 `gh-server/src/data/center.ts`
- 后台可编辑范围：首屏标题/副标题、下载条目、更新日志、FAQ（继续走内容库）；模拟器文案由研发维护

### 6.2 性能预算

- 首屏 JS（gzip）≤ 180 KB，首屏图 ≤ 300 KB
- 不引入 framer-motion / three.js / GSAP
- 星点用单个 Canvas，滚动用 `IntersectionObserver` + `requestAnimationFrame` 节流
- 模拟器预览用 CSS filter，不做真实渲染

### 6.3 无障碍

- 模拟器所有滑条用原生 `<input type="range">`，带 `aria-label`
- Tab 用 `role="tablist"` + 键盘左右切换
- 状态栏变化用 `aria-live="polite"`，但只在用户操作时播报
- 目标：axe WCAG 2.0 AA 0 违规

## 八、落地顺序

1. **P0 骨架与视觉**：新 `CenterPage` 结构、首屏、能力总览、下载与更新日志、FAQ；上线可看。
2. **P1 模拟器**：屏 3 Tab + 滑条 + 预览联动 + 状态栏。
3. **P2 场景与滚动叙事**：屏 4 场景联动、屏 5 sticky 深读。
4. **P3 设备与打磨**：屏 6 型号筛选、移动端适配、动效降级、性能与 axe 验收。
5. **P4 素材替换**：真实截图/视频上线，移除全部占位图。

## 九、验收标准

- 首屏 LCP < 2.5s（4G 模拟），CLS < 0.1
- 移动端 390px 无横向溢出，模拟器可完整操作
- 模拟器滑条操作到画面变化 < 16ms（无明显掉帧）
- 下载按钮在首屏、屏 7、页尾均可 1 次点击到达
- axe 扫描 0 违规；键盘可完成全部 Tab 切换与滑条调节
- 所有版本/大小/日期与下载中心一致，无假数据

## 十、风险与取舍

- **模拟器是「示意」不是真机**：必须显式标注，避免误导；不宣称读取真实硬件。
- **后台可编辑性下降**：方案 C 保留文案与下载可改，但结构需研发调整；若运营需要频繁改结构，再评估方案 B。
- **首屏视觉重**：深空图 + 窗口 + 星点三层叠加，需控制图片体积与绘制区域，移动端关星点。
