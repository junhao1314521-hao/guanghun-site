## 0. 结论摘要

**可以上线的前提是先解决 3 个阻断项（P0）**：

1. **域名与旧下载中心完全未迁移**：`xxrsm.com` 仍指向旧主机；新站 `GET /h-col-160.html` 命中 SPA 回退，返回 200 但渲染的是前端 404 页，不是新下载中心。产品包装/说明书上的二维码目前仍进入旧站。
2. **全站绝对 URL 仍使用 IP**：`SITE_ORIGIN=http://8.163.108.144:3002`，导致 `canonical`、`sitemap.xml`、`og:url` 全部指向 IP，切域名后 SEO 资产需重建，且已把内部地址暴露给搜索引擎。
3. **线上仍是 HTTP 明文**：无 TLS、无 HSTS，后台会话 Cookie 的 `Secure=0`。同域名上线要求 HTTPS，否则后台口令与会员数据可被链路窃听。

另有 6 项 P1（上线前修复）：下载中心 3 条资料不可用且被 sitemap 收录、SHA-256 只标类型无校验值、500 响应泄漏内部错误、无定时备份、静态下载无限流/无防盗链、`/wallpapers` 被误判 noindex。

整体完成度：前台/后台/接口/数据库主链路已打通，下载文件大小与数据库记录 100% 一致且支持 Range 断点续传；后台默认口令已验证被修改；上传白名单、表单验证码、限流、CSRF、审计日志均已落地。

## 2. P0 · 阻断上线

### P0-1 旧下载中心地址未成为新站别名，二维码会落到 404 页

- **位置**：`gh-server/src/app.ts:178`（SPA 回退）；`gh-web/src/App.tsx:291-343`（无 `/h-col-160` 路由）；`gh-web/src/App.tsx:107-155`（NotFound）
- **现状（实际运行验证）**：`GET /h-col-160.html` → `200`，返回 `index.html`，客户端渲染 NotFound；`GET /downloads` → 200，正常渲染下载中心（标题 `下载中心 · 光魂`）。
- **影响**：所有印在包装、说明书、评测卡片上的旧二维码/短链打开后看到“页面不存在”，直接造成售后咨询与品牌信任损失；搜索引擎会把该地址记为软 404。
- **复现**：`curl -s http://8.163.108.144:3002/h-col-160.html | grep '<title>'` → 返回首页标题；浏览器打开可见 404 页。
- **建议**：
  1. 前端为 `/h-col-160.html` 增加一条**与 `/downloads` 同一组件**的路由（不是 Navigate 跳转，保证地址栏不变）；
  2. `gh-server/src/lib/seoHead.ts` 的 `STATIC_META` 增加该路径，注入下载中心的 title/description 和 `canonical=/downloads`；
  3. Nginx 切流后保留 `location = /h-col-160.html` 原样 `proxy_pass` 到 3002，不做 301；
  4. 若旧站还有其他 `h-col-*.html` 在用，先导出清单再逐条映射。
- **验收**：① 直连该地址返回 200 且首屏就是下载中心；② 刷新、手机扫码、微信内置浏览器、无痕窗口均正常；③ `curl -A 'Baiduspider'` 返回的 HTML `<title>` 为“下载中心 · 光魂”；④ 地址栏 URL 不发生跳转。

### P0-2 canonical / sitemap / OG 全部指向 IP

- **位置**：`gh-server/src/routes/seo.ts:35-40`；线上 `.env` 的 `SITE_ORIGIN`
- **现状（实际运行验证）**：`/`、`/downloads` 的 `canonical` 为 `http://8.163.108.144:3002/...`；`sitemap.xml` 中 50+ 条 `<loc>` 全部是 IP。
- **影响**：迁移域名后，搜索引擎收录的是 IP 页面，正式域名权重归零；IP 暴露也会绕过域名层 WAF/CDN。
- **复现**：`curl -s http://8.163.108.144:3002/sitemap.xml | head`
- **建议**：切域名时把 `SITE_ORIGIN=https://xxrsm.com`，重启服务；确认全部 `<loc>`、`canonical`、`og:url` 变成 https 域名；IP 直接访问可保留但加 `X-Robots-Tag: noindex`。
- **验收**：`grep -c '8.163.108.144' sitemap.xml` 为 0；随机 5 个页面 canonical 均为 `https://xxrsm.com/...`；Search Console/百度站长提交新 sitemap。

### P0-3 线上无 HTTPS，后台 Cookie 非 Secure

- **位置**：`deploy/install.sh`；线上 `.env` `COOKIE_SECURE=0`、`TRUST_PROXY=0`
- **现状（实际运行验证）**：`http://8.163.108.144:3002` 直接暴露，无 443；登录响应 `Set-Cookie: gh_admin=...; HttpOnly; SameSite=Lax`，**无 Secure**。
- **影响**：管理员口令、会话 Cookie、会员手机号/订单在公网明文传输；`TRUST_PROXY=0` 在接入 Nginx 后会让限流把所有请求识别为 127.0.0.1，等于限流失效。
- **建议**：Nginx + certbot 上 443，强制 80→443；`COOKIE_SECURE=1`、`TRUST_PROXY=1`；补 HSTS（见 P1-6）。
- **验收**：`curl -I https://xxrsm.com` 有 HSTS；`http://` 301 到 https；登录 Cookie 带 `Secure`；连续请求后 `access` 日志能拿到真实客户端 IP。

### P1-5 静态下载文件无限流、无防盗链，可被批量搬运

- **位置**：`gh-server/src/app.ts:98-136`（`/uploads` 静态托管）；`gh-server/src/lib/rateLimit.ts:10-43`（仅 `/api`）
- **现状（实际运行验证）**：`/api` 限流 300 次/分钟/IP（第 298 次出现 429）；但 `/uploads/*.pdf|zip|exe` 不经过限流，`Referer: https://evil.example/` 仍返回 206；`Cache-Control: public, max-age=86400`、`Accept-Ranges: bytes`。
- **影响**：竞品/脚本可无限拉取说明书与固件；但注意**不能为此破坏正常下载**（二维码、直接粘贴链接、断点续传）。
- **建议（已确认执行）**（低维护、不影响下载）：
  1. 仅对 `/uploads` 做“每分钟每 IP 新连接数”软限流（如 60 次/分），命中返回 429 + `Retry-After`，已开始的 Range 请求不受影响；
  2. 防盗链只拦“明确的第三方页面嵌入”（Referer 非空且非本站/非白名单），空 Referer（二维码、直接打开、下载器）一律放行；
  3. 保持 `Accept-Ranges` 与 `ETag`；后续接 CDN 时改为回源鉴权，不要改用一次性签名 URL（会破坏收藏与二维码）。
- **验收**：连续 200 次新连接后出现 429 且能自动恢复；手机扫码、复制链接到新窗口、IDM 断点续传均成功；第三方站点 `<a href>` 下载被拒、直接粘贴仍可用。

### P1-6 安全响应头不完整（无 CSP / 无 HSTS）

- **位置**：`gh-server/src/app.ts:50-66`
- **现状（实际运行验证）**：有 `X-Content-Type-Options: nosniff`、`X-Frame-Options: SAMEORIGIN`、`Referrer-Policy: strict-origin-when-cross-origin`；**无** `Content-Security-Policy`、`Strict-Transport-Security`、`Permissions-Policy`。
- **影响**：XSS 兜底缺失；HTTPS 上线后无 HSTS 仍可被 SSL Strip。
- **建议**：上 TLS 后加 `Strict-Transport-Security: max-age=15552000; includeSubDomains`；CSP 用 Report-Only 跑一周再转正式（至少 `default-src 'self'`，`img-src 'self' data: https:`，`object-src 'none'`）。
- **验收**：`curl -I` 可见两个头；Report-Only 期间无业务告警；后台页面功能正常。
